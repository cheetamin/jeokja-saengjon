# 적자생존. — 설치 및 사용 설명서
버전 0.1.2 · 2026년 11월 16일 · Windows 10/11 x64용 1차 시범 프로그램

## 먼저 읽기
작동하는 로컬 기록 프로그램과 Windows 실행 파일을 제공합니다. 별도 Node.js 설치나 브라우저 주소 입력은 필요하지 않습니다. 실제 Windows 바탕화면 실행, Windows 한글 IME, 실제 Google 계정 로그인 및 전송, 실제 나이스 업로드는 아직 검증하지 않았습니다. 최초 시험에는 가상 학생만 사용하세요. Google 미연결 상태에서 상담 자료는 외부로 전송되지 않습니다.

## 1. 설치 — 한 번만 진행
1. JeokjaSaengjon-Windows-0.1.2.zip을 내려받습니다.
2. ZIP 파일을 마우스 오른쪽 버튼으로 눌러 **모두 압축 풀기**를 선택합니다. ZIP 안에서 바로 실행하지 마세요.
3. 압축을 푼 폴더에서 **Install.cmd**를 더블클릭합니다. 관리자 권한 없이 현재 Windows 사용자 영역에 앱을 복사하고 바탕화면·시작 메뉴 바로가기를 만듭니다.
4. 설치 후 앱이 열립니다. 이후에는 바탕화면의 **적자생존** 아이콘을 더블클릭합니다.
5. 12자 이상의 보관함 비밀번호를 정합니다. 비밀번호는 Google 비밀번호와 다르게 정하고 별도로 안전하게 보관하세요. 분실 시 복구할 수 없습니다.

앱 위치: `%LOCALAPPDATA%\Programs\JeokjaSaengjon`
자료 위치: `%APPDATA%\JeokjaSaengjon\records.jjvault`

설치가 막히면: 조직 정책이나 보안 프로그램을 임의로 해제하지 말고 학교 관리자에게 확인하세요. 이 패키지는 코드 서명 인증서가 없어 Windows에서 알 수 없는 게시자로 표시될 수 있습니다. 설치 스크립트의 전체 내용은 Install.ps1에 있습니다. 인터넷 다운로드·관리자 권한·자동 시작 등록은 하지 않습니다.

스크립트를 사용할 수 없는 환경: 압축을 푼 `app` 폴더를 개인 프로그램 폴더에 보관하고 그 안의 `JeokjaSaengjon.exe`를 실행합니다. EXE를 오른쪽 클릭하여 ‘보내기 → 바탕 화면에 바로 가기 만들기’를 사용합니다. 아이콘 변경 시 같은 폴더의 `icon.ico`를 선택합니다. EXE만 따로 이동하면 안 됩니다.

업데이트: 앱을 닫고 새 버전의 Install.cmd를 실행합니다. 프로그램 폴더와 데이터 폴더가 분리되어 기존 자료를 유지합니다. 업데이트 전 암호화 백업을 권장합니다.
삭제: Uninstall.cmd를 실행하고 REMOVE를 입력하면 프로그램과 바로가기만 삭제합니다. 상담 자료·백업은 보존됩니다. 자료까지 폐기할 때는 학교 지침에 따라 데이터 폴더, 별도 백업, 내보낸 엑셀과 Google 파일을 각각 처리해야 합니다.

## 2. 첫 기록 만들기
1. 설정 → 우리 반 설정에서 학년도·학년·반을 저장합니다.
2. 설정 → 학생 명단에서 **가상 학생 3명 등록**으로 먼저 시험합니다. 실제 명단 등록은 승인된 환경인지 확인한 후 진행합니다.
3. 기록하기 → 학생 선택 → 제목·내용 입력 → 상담 시간 확인 → **저장하기** 또는 Ctrl+S.
4. ‘상담 기록이 저장되었습니다.’는 **로컬 암호화 파일 저장 성공**을 뜻합니다. Google 전송 완료를 뜻하지 않습니다.
5. 기록 조회에서 학생·기간·학년도·대상·키워드로 검색합니다. 왼쪽 기록을 선택하면 오른쪽에 상세 내용이 나옵니다.

기록창은 560px 너비로 시작하고 조회/설정은 최대 1120px로 확장합니다. 화면 높이에 맞추고 내부 스크롤을 사용합니다. Windows 기본 제목 표시줄로 최소화·크기 변경·닫기를 할 수 있도록 구성했습니다. 실제 Windows 화면 배치 검수는 남아 있습니다.

## 3. 명단과 학년도
엑셀/CSV 첫 행은 `번호`, `이름`(또는 `성명`), `성별`을 사용합니다. 성별은 남·여·혼성 또는 빈칸입니다. 파일은 5MB 이하, 한 번에 1~200명입니다. UTF-8 CSV를 권장합니다. 첫 시트만 읽습니다.
파일을 선택해도 즉시 등록하지 않습니다. 미리보기 확인 후 ‘명단 등록 확정’을 누릅니다. 같은 학년도·학년·반·번호는 기존 학생 정보 수정으로 처리됩니다. 전학생은 새 번호를 사용하세요. 동일 번호를 다른 학생에게 재사용하지 마세요.
학생 정보의 ‘수정’을 통해 이름·번호·재학 상태를 바꿔도 내부 ID는 유지됩니다. 전출 학생은 명단에서 전출로 바꾸고 상담 기록은 보존합니다. 과거 기록의 학생 표시는 당시 정보를 유지하며 현재 학생 ID 필터로 연결됩니다.
새 학년도는 설정의 학년도를 바꿔 저장한 뒤 새 명단을 등록합니다. 예전 명단과 기록은 남습니다.

## 4. 작성 중 내용, 수정, 휴지통
입력 변경 시 암호화 임시저장을 요청합니다. 정상 종료에서는 대기 중인 로컬 저장을 마친 뒤 닫습니다. 디스크 오류가 생기면 오류를 표시하고 창 닫기를 중단합니다. 강제 종료·전원 차단 직전의 입력은 보장하지 않습니다.
기록 수정은 동일 상담 ID를 갱신합니다. 수정 시 비식별 게시 승인이 해제됩니다. 작성 중인 초안이 있는데 다른 기록을 수정하려 하면 초안 폐기 여부를 확인합니다.
삭제는 휴지통 이동이며 복원할 수 있습니다. Google에 전송했던 자료는 연결 후 해당 행의 내용이 비워지고 관리 ID와 삭제 상태만 남습니다. 미연결 상태에서는 원격 삭제가 끝나지 않습니다.
보존 검토 기간을 설정할 수 있으나 자동 영구 삭제는 하지 않습니다. 휴지통 및 과거 암호화 백업에도 기록이 남을 수 있습니다. 완전한 폐기는 별도 정책에 따라 처리해야 합니다.

## 5. Google Sheets 설정 — 학교 승인과 관리자의 작업 필요
이 앱은 ChatGPT의 연결된 Google 계정 권한을 가져오지 않습니다. 개인 Gmail 또는 학교 Workspace 계정으로 앱 자체의 OAuth 연결을 설정해야 합니다. 0.1.2부터 설정에서 계정 종류를 선택할 수 있습니다. 개인 Gmail은 학교의 저장 환경 승인을 의미하지 않습니다.

관리자 준비:
1. 승인된 Google Cloud 프로젝트에서 Google Sheets API와 Google Drive API를 사용 설정합니다.
2. Google Auth Platform/OAuth 동의 화면을 조직 정책에 맞게 구성합니다. 조직 내부 앱 설정을 사용할 수 있다면 내부로 설정합니다. 테스트 상태는 허용된 테스트 계정을 등록합니다.
3. OAuth 클라이언트 유형을 **데스크톱 앱**으로 만들고 클라이언트 JSON을 다운로드합니다. 웹 앱 유형은 사용하지 않습니다.
4. 학교의 OAuth 앱 접근 정책에서 해당 클라이언트와 요청 범위를 허용할지 관리자가 판단합니다.

앱에서:
1. 설정 → 승인된 계정 이메일 입력 → 학교의 저장 환경 사용 승인 확인 → **설정 저장**.
2. **OAuth JSON 등록**으로 받은 데스크톱 클라이언트 JSON을 선택합니다.
3. **Google 연결**을 누르고 기본 브라우저에서 승인된 Workspace 계정으로 로그인합니다. 로그인 완료 후 앱으로 돌아옵니다.
4. 가상 상담 한 건을 저장하고 기록 조회에서 A/B/C 각각의 상태와 실제 파일을 확인합니다.

인증은 시스템 브라우저 + PKCE + 127.0.0.1 임시 콜백을 사용합니다. HTTP는 동일 PC의 OAuth 콜백에만 사용하고 Google 요청은 HTTPS입니다. 요청 범위는 openid, email, drive.file입니다. 모든 드라이브 파일을 읽는 범위를 요청하지 않습니다. OAuth JSON 및 토큰은 렌더러 화면에 전달하지 않고 보관함 안에 암호화하여 저장합니다. 학교 정책상 OAuth 클라이언트를 만들 수 없으면 로컬 모드만 사용하세요.

파일은 학년도별로 **서로 다른 스프레드시트 3개**를 생성합니다:
- A: 적자생존_개인상담기록_2026 — 실명·원문, 소유자 전용
- B: 적자생존_가명상담기록_2026 — 교사 검토 승인한 제목·내용만 게시, 소유자 전용
- C: 적자생존_나이스제출용_2026 — 필수 분류 확인을 마친 기록만 게시, 소유자 전용

이번 버전은 앱이 새로 생성한 파일을 관리합니다. 임의의 기존 파일 ID 입력 기능은 제공하지 않습니다. 파일 공유를 소유자 외 사용자·그룹·조직·링크 공개로 바꾸면 전송을 차단합니다. B도 공개 공유용이 아닙니다. 독립 파일이므로 나중에 각 접근 권한을 별도로 관리할 수 있지만 이 버전의 자동 동기화는 소유자 전용 정책입니다.

## 6. 동기화 상태와 충돌
저장 직후 로컬 결과를 표시하고 Google 전송은 별도로 진행합니다. 연결된 경우 시작 시, 저장/수정/삭제/승인 후 및 약 1분 주기로 재시도합니다. 통신이 안 되어도 로컬 입력·저장은 계속됩니다.
- 저장 완료: 해당 파일의 해당 상담 버전 반영 성공
- 교사 검토 대기: B 게시 승인 필요. 이전 승인 사본이 있으면 철회 대상
- 필수 항목 확인 필요: C 분류·필수값 확인 필요
- 동기화 실패 / 재시도 필요: 전송 미완료
- 충돌: 원격 직접 수정, 관리 ID 손상, 공유 권한 변경 등을 확인해야 함

세 파일은 각각 독립적으로 처리됩니다. 모두 완료되지 않으면 전체 완료로 간주하지 않습니다. 각 파일의 숨김 `_관리` 시트에 상담 ID·버전·행 해시·상태를 저장합니다. C의 입력 시트는 16열을 그대로 유지하므로 상담 ID는 `_관리`의 같은 행에서 연결합니다. `_관리`를 삭제하거나 편집하지 마세요.

기록 원본은 앱입니다. Google 파일은 읽기용 사본으로 사용하세요. 원격 행 직접 변경을 탐지하면 자동 덮어쓰기를 멈춥니다. 실제 상담의 내용을 변경하려면 앱에서 수정하세요. 실수로 시트를 수정했다면 Google 버전 기록에서 해당 변경 전 상태로 복원하고 재시도합니다. 원격 변경을 앱으로 자동 병합하는 기능은 없습니다. 동시에 다른 프로그램이 시트를 수정하는 경쟁 상황을 완전히 차단하는 서버 잠금 기능도 없습니다.

파일 생성 응답이 유실되면 저장한 생성 작업 식별자로 기존 파일을 검색합니다. 확인되지 않으면 새 파일을 계속 만드는 대신 ‘생성 응답 확인 대기’로 멈춥니다. 검색 재시도 후에도 해결되지 않으면 관리자가 Drive의 생성 여부와 권한을 점검해야 합니다.
Google 로그아웃은 로컬 토큰을 제거하고 폐기를 요청합니다. 네트워크 오류 시 Google 계정의 연결된 앱 관리에서도 권한을 회수하세요. 이미 생성한 파일은 로그아웃만으로 삭제되지 않습니다.

## 7. 비식별 검토
기록 조회 → 비식별 결과 검토에서 이름, 전화, 이메일, 일부 학교명·주소·식별번호를 가린 초안을 확인합니다. 설정의 추가 가림 목록에 보호자 이름과 학교명 등도 등록할 수 있습니다. 자동 탐지는 일부 패턴만 다루며 완전한 익명화를 보장하지 않습니다.
제목과 내용에서 가족관계·사건·지역처럼 맥락으로 식별되는 정보까지 직접 고친 뒤 **검토 완료·게시 승인**을 누릅니다. 승인되지 않은 원문은 B로 전송하지 않습니다. 원문·가명 방식·가림 목록 변경 시 기존 승인을 해제하고 연결 시 기존 B 내용을 철회합니다. 오프라인이면 철회도 연결 후 수행됩니다.

## 8. 나이스 엑셀
기록하기 → 후속 지도·나이스 세부 분류를 펼치고 원본 참조값으로 분류를 선택합니다. 일반상담의 대분류는 원본에 따라 상담/의뢰입니다. 대분류 → 중분류 → 상담구분이 연결됩니다. ‘교사 분류 확인’을 체크하세요.
기록 조회에서 개별 기록 또는 현재 조회 결과 전체를 엑셀로 저장합니다. 미확인 값이 하나라도 있으면 해당 기록을 안내하고 내보내기를 중단합니다. 한 파일 최대 3,170건입니다. 상담 시간은 시/분으로 나누고 상담일자는 YYYYMMDD 문자열로 기록합니다.
첨부 원본의 입력/참조 시트, 16열 순서, 정의된 이름, 확장 유효성 정보를 보존합니다. 원본 ZIP에서 입력 시트의 데이터 영역만 추가하는 방식을 사용합니다. 제목·본문은 수식이 아닌 문자열로 저장합니다.
실제 나이스에 업로드해서 검증하지 않았습니다. 업로드 성공이나 완전한 호환성을 보증하지 않습니다. 먼저 가상 사례 또는 학교에서 허용한 소량 자료로 서식 검사를 진행하세요. Google C는 동기화용 사본이며 나이스 업로드에는 앱에서 다운로드한 XLSX를 사용하세요.

## 9. 백업과 보호
설정 → 암호화 백업 저장. 현재 보관함 비밀번호로 복원합니다. 백업에서 Google 인증 정보는 제외합니다. 복원 시 기존 자료를 교체하므로 먼저 현재 자료를 백업하세요. 복원 직전 파일은 데이터 폴더에 before-restore 시각 이름으로 추가 보존합니다. 평소에는 직전 암호화 파일인 `.previous`도 유지합니다.
잠금 버튼 또는 10분 비활동 시 보관함이 잠깁니다. 잠금 상태에서도 Windows 화면 보호·계정 잠금을 함께 사용하세요. 앱 암호화는 PC 악성코드나 잠금 해제 상태의 다른 사람 접근을 막는 보안 제품이 아닙니다.
실제 학생 자료 입력 전 학교·교육청의 저장 위치, 계정, 보존 기간, 상담 기록 처리 지침을 확인하세요. 이 설명서는 특정 교육청의 적합성 승인을 의미하지 않습니다. 평문 XLSX, USB, 이메일, 공유 폴더 및 별도 백업의 관리도 필요합니다. 상담 자료는 외부 분석·오류 수집 서비스로 보내지 않습니다.

## 10. 검증 범위
자동 검증 결과는 TEST_RESULTS.md에 있습니다. Node 기반 실제 저장/내보내기 처리와 React DOM 상호작용, 가짜 Google API를 이용한 동기화 오류 검사를 수행했습니다. Electron의 실제 native 창은 이 환경의 소켓 제한으로 실행하지 못했습니다. DOM 검사는 Windows IME·픽셀 배치·바탕화면 아이콘 확인을 대신하지 않습니다.

## 개발자 재현
소스 ZIP 압축 해제 → Node.js 설치 환경에서 `npm ci` → `npm run build` → `npm test` → `npm start`. Windows 패키지는 `npm run pack:win`. 패키지 폴더 전체가 실행에 필요합니다. 테스트는 실제 Google 요청을 보내지 않으며 가상 자료만 씁니다.

## 0.1.3 명단 양식과 여러 학생 공동 지도
설정 → 학생 명단 → **엑셀 양식 다운로드**를 누릅니다. `명단` 시트 첫 행을 유지하고 2행부터 번호와 이름을 작성합니다. 성별은 남·여·혼성 또는 빈칸입니다. 작성 안내 시트는 업로드하지 않으며 앱은 첫 명단 시트를 읽습니다. 학년도·학년·반을 앱에서 먼저 저장한 뒤 명단을 불러오고 미리보기를 확인하세요. 기존 번호는 해당 학생의 정보를 수정하므로 전학생에게 이전 학생 번호를 재사용하지 마세요.

기록하기에서 학생을 고른 뒤 **여러 학생 함께 선택**을 펼쳐 추가 학생을 체크합니다. 체크 해제로 참여 학생을 뺄 수 있습니다. 공동 지도는 모든 참여 학생의 조회에 같은 상담 ID로 나타나고 상담 횟수에 각각 1건으로 포함됩니다. 공동 기록 자체는 1건이므로 전체 내보내기에서 인원수만큼 중복 생성하지 않습니다. 참여자를 수정하면 같은 ID로 갱신하고 비식별 승인은 해제됩니다. 이름·번호 변경 후에도 학생 ID로 조회됩니다. 같은 학년도·학급 학생만 함께 선택할 수 있습니다.

학생 상담의 선택 인원으로 나이스 인원과 집단상담 분류를 제안합니다. 교사가 공식 분류·상담구분을 직접 확인하세요. 학부모 상담의 실제 참석 인원은 직접 수정할 수 있습니다. 공동 내용과 구분해야 하는 개인별 민감한 내용은 별도 기록으로 작성하세요.

업데이트 전에 암호화 백업을 저장하세요. 0.1.3은 이전 1인 기록을 읽고 새 보관함 형식으로 저장합니다. 새 형식은 이전 앱으로 열 수 없습니다. 여러 컴퓨터 간 자동 병합은 지원하지 않습니다.


## 0.1.4 학생 검색과 쉬는 시간
학생 검색에 이름 일부, 초성 또는 번호를 입력하면 검색 결과 버튼이 나타납니다. `김민수`, `ㄱㅁㅅ`, `8`, `8번`, `8번 김민수`처럼 검색할 수 있습니다. 숫자만 입력하면 정확한 번호만 찾습니다. 검색 결과 한 명일 때 Enter로 선택하거나 결과 버튼을 누르세요. 한글 조합 중 Enter로는 선택하지 않습니다. 검색어를 지우면 현재 학급의 재학생 목록을 다시 볼 수 있습니다. 결과가 없으면 설정에서 학년도·학년·반과 재학 상태를 확인하세요. 기존 상담 수정 중에는 그 상담의 학급 학생을 찾습니다.

설정 → 우리 반 설정 → 학교별 수업 시간표를 펼치면 1~4교시 쉬는 시간, 점심 시간, 등교 전·방과후의 시작·종료도 각각 지정할 수 있습니다. 시각을 고친 뒤 **설정 저장**을 누르세요. 기록하기에서 해당 교시를 선택하면 설정 시각이 입력되며 실제 상담 시각은 따로 수정할 수 있습니다. 기존 수업 시간은 덮어쓰지 않습니다. 새로 추가된 시간은 예시이므로 점심 위치와 수업 순서를 포함해 학교 시간표에 맞게 확인해 주세요. 시간표 변경은 이전에 저장한 상담의 시각을 바꾸지 않습니다.


## 0.1.5 앱 내 업데이트
Windows에서는 새 Setup.exe를 한 번 설치한 후 설정 → 프로그램 업데이트에서 **확인 → 다운로드 → 재시작하여 적용**을 사용합니다. 다운로드 중에도 기록할 수 있고, 적용 전에 저장과 자동 암호화 백업을 진행합니다. 다운로드 후 단순히 앱을 닫으면 설치하지 않습니다. 기존 ZIP 설치본은 Setup.exe 설치가 필요합니다. 현재 Mac 빌드는 정식 Apple 개발자 서명이 없어 확인·수동 다운로드만 제공합니다. 자세한 절차와 백업 위치는 AUTO_UPDATE.md를 참고하세요.
